# Career Talent Platform — ملف التنفيذ والتسليم

تاريخ العمل: 11 أكتوبر 2026. المرجع البصري هو صورة البروفايل المهني وبحث الشركات المرفقة مع الطلب، وليس بيانات الأشخاص أو النسب الموجودة في الصورة.

هذا الملف يصف الإصدار الجديد للبروفايل المهني واكتشاف المواهب. ملفات التسليم السابقة تبقى مرجعًا تاريخيًا للصور الخاصة والكورسات والشهادات والكارت والـCV؛ وصف التبويبات الأربعة والثيم الثابت في التقارير القديمة لم يعد وصفًا لهذا الإصدار.

## 1. النطاق والنتيجة

- بروفايل مهني متصل بالبيانات الحقيقية، وليس لوحة ألعاب للشركات.
- بحث شركات حقيقي في الأشخاص الذين وافقوا صراحة على اكتشافهم فقط.
- معاينة مرشح، أعمال محاكاة، مهارات مسنودة بالدليل، كورسات وشهادات بحسب اختياراته.
- قائمة مختصرة محفوظة بالخادم ومعزولة لكل مساحة شركة/مسؤول.
- طلب تواصل داخلي آمن؛ لا كشف تلقائي للبريد أو الهاتف.
- الحفاظ على نظام الحسابات وBetter Auth والـCV الإنجليزي والكارت العام الحالي.
- لا مدفوعات، لا وظائف وهمية، لا ATS توظيف كامل، لا نسب ملاءمة مختلقة، ولا إعادة ضبط للإنتاج.

## 4. بروفايل المالك

المسار: `/ar/career-profile` أو `/en/career-profile`.

التبويبات:

1. Overview / نظرة عامة.
2. Skills / المهارات.
3. Practical Work / الأعمال العملية.
4. Courses / الكورسات.
5. Certificates / الشهادات.
6. Career Journey / الرحلة المهنية.
7. CV / السيرة الذاتية.

تستمر روابط التحرير الشخصية والمهنية، عمليات الكورسات والشهادات، إدارة الصورة، إعدادات المشاركة والكارت. يحتفظ التبويب بمساره عبر hash.

### Hero وCareer Pass

الاسم، الدور، المكان، الملخص، حالة التوفر والروابط من الحساب الفعلي. اكتمال البيانات موصوف باعتباره **اكتمال بيانات شخصية، وليس تقييم مهارات أو جاهزية توظيف**.

Career Pass يعرض اسم الحساب ودوره ومكانه، ومعرّف مشاركة مشتقًا من رمز الرابط العام، لا رقم المستخدم الداخلي. يتولد QR محليًا فقط عند تفعيل رابط عام حقيقي؛ خلاف ذلك تظهر حالة Private by default. زر الكارت يفتح إعدادات المشاركة والتصدير السابقة.

تصدير PNG المحلي وخيار تضمين الصورة محفوظان في محرر الكارت الأصلي. اختيار صورة الكارت لا يضيفها تلقائيًا إلى الصفحة العامة أو الـCV. QR العام لا يفتح الملف الخاص أو ملف اكتشاف الشركات.

### Overview

عمود للمعلومات الأساسية والنبذة والروابط، ومساحة رئيسية للأعداد الفعلية والهدف المهني ومهارات الممارسة وأعمال المحاكاة والشهادات. تعرض النظرة العامة أول ست مهارات مع رابط كل المهارات لتقليل الزحام.

الأعداد من البيانات الفعلية: مهارات لها دليل، كورسات حالتها completed، شهادات أضافها المالك، وأنشطة تدريبية مميزة حسب activityId. البيانات غير المحملة تظهر `—`، لا عددًا وهميًا.

مجالات التطوير التالية تأتي من متطلبات الدور الموجودة في catalog التي لا توجد لها ممارسة مسجلة، دون نسبة Hiring Readiness.

### الرحلة المهنية

عرض زمني مهني للمراحل المنفذة في هذا الجزء: أساسيات المحاسبة ثم First Shift، مع العدد الفعلي للمهمات وروابط استكمالها. لا تمت إضافة Month-End أو Senior Track وهمي لإكمال الرسم. دليل المهارات والـCV يظلان متصلين بنتائج العمل.

## 5. الأدلة واللغة المهنية

- Practiced: توجد ممارسة وفق نظام الأدلة الحالي.
- Demonstrated: تحقق المستوى وفق قواعد الأدلة القائمة.
- Verified: لا يستخدم إلا عندما يعيد نظام الأدلة الحالي هذا المستوى؛ ليس نتيجة رفع شهادة.
- نسبة الشريط هي تقييم الدليل التدريبي الموجود، وليست Match% أو حكم توظيف.
- الكورسات والشهادات الخارجية self-reported ولا تولد أدلة مهارة تلقائيًا.
- أعمال المحاكاة موسومة Training Simulation، وليست Employment.
- لا XP أو عملات أو ألقاب خيالية في واجهة الشركات.

الأعمال المقبولة تبنى من `student-unit1` ذي provenance `SERVER` فقط: اليومية، أستاذ النقدية، ميزان المراجعة وورقة العمل حسب قبول مهامها. لا مشروعات إنتاج وهمية.

## 6. ثلاثة حدود خصوصية مستقلة

| السياق | من يستطيع الوصول؟ | ما الذي يتحكم في العرض؟ |
| --- | --- | --- |
| ملف المالك الخاص | الحساب نفسه | ملكية الجلسة بالخادم |
| رابط Portfolio العام | حامل رمز المشاركة المفعّل | قواعد المشاركة العامة القائمة |
| اكتشاف الشركات | مسؤول لديه مساحة شركة منشأة بالخادم | موافقة اكتشاف مستقلة وحقول اختيارية |

التسجيل أو Open to Work لا ينشر المستخدم تلقائيًا. تفعيل اكتشاف الشركات لا يفعّل الرابط العام. وجود رابط عام لا يفعّل اكتشاف الشركات.

### الموافقة

كل الإعدادات افتراضيًا false:

`enabled`, `photo`, `location`, `education`, `languages`, `socials`, `courses`, `certificates`, `cv`, `contactRequests`.

الموافقة الأساسية تعرض الاسم والدور والمستوى والتوفر والملخص وأدلة المهارات والأعمال المقبولة. بقية الحقول منفصلة، ويشرح نموذج المالك ما سيظهر.

لا تظهر للشركات حقول البريد والهاتف أو userId أو صور الشهادات أو credentialId أو الملاحظات الخاصة. حتى اختيار CV لا يكشف البريد والهاتف الأصليين.

عند إلغاء الموافقة تُمسح الإسقاطات من نتائج البحث، ويتوقف العرض المباشر ومعاينة CV، وتُخفى من القائمة المختصرة. عند إعادة التفعيل يولّد الخادم معرّف اكتشاف جديدًا؛ روابط وقوائم قديمة لا تعود للعمل تلقائيًا. لا يمكن استرجاع نسخة التقطها شخص قبل الإلغاء؛ هذا قيد طبيعي لأي عرض مصرح سابقًا.

## 7. الحد الأدنى للخادم دون تغيير Prisma

لم تتم إضافة جداول أو migrations أو تغيير USER/ADMIN أو reset قاعدة البيانات. استُخدم نموذج `CloudProgress` الموجود، بحدود namespace جديدة لا يستطيع مسار النسخ الاحتياطي القديم كتابتها:

| Domain | المالك | المحتوى |
| --- | --- | --- |
| `talent/company` | مسؤول الشركة | بيانات مساحة شركة + صلاحية OWNER مشتقة بالخادم |
| `talent/discovery` | المرشح | موافقة + إسقاط آمن قابل للبحث + UUID اكتشاف |
| `talent/shortlist/<discovery-id>` | مسؤول الشركة | حفظ مرشح لمجال الشركة الخاص به |
| `talent/contact/<company-id>` | المرشح | آخر طلب داخلي من الشركة |

كلها provenance `SERVER`. لا تقبل النسخة القديمة `talent/*`، ولا تدرج هذه المجالات في نسخة me/progress المرسلة للعميل.

الإسقاط الآمن يستعمل allowlist، لا إرسال كائن الملف الخاص الكامل. الكتابات التي تؤثر في البروفايل والـCV والصورة والكورسات والشهادات والشوكيز والأدلة تحدث إسقاط الاكتشاف داخل transaction نفسه. لا يلزم أن يلغي المالك موافقته ويعيد تفعيلها لتحديث بياناته.

## 8. صلاحيات الشركة

- الحساب العادي لا يستطيع قراءة البحث أو الـShortlist أو مرشح عن طريق URL بدون مساحة شركة خادمية.
- التسجيل المهني للشركة عملية صريحة منفصلة، ببيانات الاسم ومسؤولها والقطاع والمكان ورابط HTTPS اختياري.
- الخادم يولد هوية المساحة وصلاحية OWNER؛ لا يقبل role أو userId أو companyId في payload النموذج.
- ليست ترقية USER إلى ADMIN، وليست شركة Verified.
- هذه المرحلة مساحة شركة بمسؤول واحد؛ ليست نظام عضويات فرق متعددة.
- عزل القائمة المختصرة يعتمد على userId المشتق من Better Auth بالخادم، لا على قيمة مختارة بالعميل.
- واجهة الشركة مستقلة عن تهيئة اللعبة ونسخ بيانات التدريب إلى المتصفح.
- الجلسة وOrigin وX-Account-Context وحدود الطلبات والاستجابة no-store تبقى فعالة.

## 9. البحث والمعاينة

البحث server-side عبر استعلام PostgreSQL parameterized إلى إسقاطات `talent/discovery` المسموح بها فقط، وليس تحميل سجل المستخدمين الكامل إلى المتصفح.

الحقول: الاسم، الدور، مسميات المهارات، التعليم المسموح. الفلاتر: الدور، المهارة، المكان، التعليم، التوفر، مستوى الخبرة. المكان والتعليم لا يقبلان البحث في قيم أخفاها المالك.

Pagination: عشرون نتيجة في الصفحة، إجمالي حقيقي، ترتيب آخر تحديث ثم UUID ثابت. الصفحة خارج النتائج تعيد قائمة فارغة مع الإجمالي الصحيح. المدخلات bounded وstrict.

المعاينة تعيد فحص الموافقة وتحسب البيانات من المصدر الحالي داخل transaction؛ UUID ليس تصريح وصول إلى ملف خاص.

التبويبات: Overview / Skills / Projects / Certificates / CV. العرض الكامل متاح بمسار مرشح محمي. شهادات الشركات metadata فقط، مع self-reported، بدون صور خاصة.

### قرار Match Score

لا AI Match ولا نسب 78% أو 60% مستعارة من الصورة. عند تحديد مهارة مطلوبة يعرض عدد المتطلبات الصريحة الموجودة: matched / requested. الصيغة تقاطع معرفات مهارات الممارسة مع المتطلبات الفريدة، وليس تقدير تأهيل أو توظيف.

## 10. Shortlist والتواصل

- الحفظ في قاعدة البيانات، لا localStorage.
- Add مكرر idempotent، Remove خاص بالمالك.
- حد 100 عنصر لكل مسؤول.
- القائمة تُحمّل المرشحين الذين ما زالوا ظاهرين فقط؛ الشركة B لا ترى قائمة A.
- طلب التواصل يشترط موافقة contactRequests، ويوضع في inbox المرشح الخاص.
- لا بريد صادر تلقائيًا، لا كشف رقم هاتف، لا رسائل أو ملاحظات خاصة منشورة للعامة.
- رسالة واحدة محدثة لكل شركة/مرشح، 10–1000 حرف، مع حدود الطلبات الحالية.
- اسم الشركة ومسؤولها ورابطها ذاتي التصريح، ولا ادعاء تحقق من هوية الشركة.

## 11. الحفاظ على CV والكارت

لم يتم إعادة بناء محرك CV. الإنجليزية/LTR، حد صفحتين A4، بدون صورة أو QR أو ATS Score، والمحاكاة منفصلة عن العمل الفعلي. كورسات وشهادات المالك تبقى متصلة بالمحرك الحالي وحدوده.

معاينة CV للشركة تتطلب موافقة مستقلة، وتستخدم `compactCv` نفسه بعد إزالة الاتصال الأصلي والحقول غير المسموح بها. هي معاينة نصية آمنة داخل البانل، وليست تنزيلًا للـCV الخاص الكامل. المالك ما زال يستطيع Preview / Print / Save PDF من صفحته.

الكارت PNG والـQR المحلي وبطاقات الإنجاز ومعاينة الأعمال وإلغاء رمز المشاركة مستمرة. لا مزود QR خارجي.

## 12. المسارات

كل مسار واجهة له `/ar` و`/en` فعليان:

- `/career-profile` — ملف المالك.
- `/career-profile/cv` — CV الخاص القائم.
- `/companies` — تعريف الشركات.
- `/employer` — مدخل الشركة.
- `/employer/company` — إنشاء/تعديل مساحة الشركة.
- `/employer/candidates` — البحث المحمي.
- `/employer/candidates/<uuid>` — معاينة كاملة محمية.
- `/employer/shortlist` — القائمة الخاصة.
- `/portfolio/<token>` — رابط المشاركة العام القائم.

مسارات `/companies/talent` و`/employers/talent` والـcandidate القديمة توجّه إلى التطبيق المحمي الجديد، لا إلى قائمة Demo. `/employers` يبقى صفحة تعريف عامة حقيقية وفق عقد المسارات canonical السابق.

## 13. API غير محلي اللغة

تحت `/api/v1/`:

| Method | Path | الحد الأمني |
| --- | --- | --- |
| GET/PUT | `me/discovery` | مالك الجلسة + revision |
| GET | `me/contact-requests` | Inbox المالك |
| GET | `employer/account` | حساب الجلسة، لا قائمة مستخدمين |
| PUT | `employer/company` | إنشاء capability خادمي محدود |
| GET | `employer/candidates` | صلاحية شركة |
| GET | `employer/candidates/<uuid>` | صلاحية + موافقة حالية |
| GET | `employer/candidates/<uuid>/cv` | صلاحية + موافقة CV |
| GET/PUT | `employer/shortlist` | نطاق المالك فقط |
| POST | `employer/contact` | صلاحية + موافقة تواصل |

Better Auth يبقى `/api/auth/*` دون locale rewrite. لا تعديل لمسار Google أو قواعد المحاسبة في هذا الإصدار.

## 14. SEO والكاش

واجهة الشركات الخاصة noindex، no-store وno-referrer؛ server layout يطلب الجلسة، ويحوّل الزائر المجهول إلى login محلي موجود مع next داخلي آمن. مسار البحث القديم الخاص أُزيل من sitemap/publicRoutes، مع اختبار منع رجوعه. الصفحة التعريفية `/employers` تبقى عامة.

الصفحات الخاصة والعامة ذات الرمز تحتفظ بقيود الخصوصية السابقة. لا فهرسة لبيانات مرشحين خاصة.

QA الشركات يستخدم قاعدة `talent_utf8_test` المحلية فقط على 127.0.0.1، مع أربع جلسات منفصلة وبيانات fixtures محلية للعدد 0 و1 و23. لا يقرأ اتصال الإنتاج ولا يضيف أشخاصًا وهميين إليه. قاعدة UTF-8 صريحة لتجنب ترميز ويندوز الافتراضي.

مقاسات الشركات: 1920×1080، 1440×900، 1024 tablet، 390×844. البروفايل: 1920، 1440، 390. اللغتان والثيمان، وعدم overflow، مع اختبارات JSON حقيقية للبحث والـpagination والخصوصية والعزل وإلغاء الموافقة.

## 18. حدود هذه المرحلة

- مساحة الشركة ذات مسؤول واحد، self-reported؛ لا تحقق هوية أو فرق مشتركة أو دعوات عضوية.
- لا إضافة وظائف أو pipeline طلبات أو مدفوعات أو رسائل بريد صادرة.
- البحث يعتمد PostgreSQL JSON projection داخل namespace محدد؛ يحتاج نموذجًا مفهرسًا أكثر تخصصًا عند التوسع الكبير.
- محدودية الشهادات: نص بإذن المالك، لا مشاركة صور أو اعتماد مهني.
- لا خوارزمية توظيف/AI؛ تقاطع مهارات مطلوب فقط.
- الأعمال البارزة مصدرها المهام المقبولة الموجودة؛ لا تكملة وهمية للمراحل غير المكتملة.
- حد shortlist 100. الرسالة الداخلية الأحدث لكل شركة فقط، والـinbox آخر 20 طلبًا.
- إلغاء المشاركة يوقف الوصول اللاحق، ولا يمحو نسخًا حفظها الآخرون سابقًا.
- نجاح QA المعزول ليس دليلًا على تجربة حساب مرشح حقيقي في الإنتاج؛ التحقق الإنتاجي المعلن يجب أن يحدد إن كان read-only.
