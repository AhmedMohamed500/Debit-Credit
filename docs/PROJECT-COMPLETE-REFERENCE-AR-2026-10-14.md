آخر مراجعة شاملة: **22 أكتوبر 2026 — توقيت القاهرة**.

هذا ملف مستقل لتسليم المشروع وفهمه واستكماله. يجمع المنتج، تاريخ التطوير، المنهج، الأنظمة المحاسبية، رحلة المستخدم، البروفايل والـCV، أصحاب العمل، البنية التقنية، البيانات والخصوصية، الاختبارات، النشر، والناقص فعلًا.

**لا يحتوي الملف على كلمات مرور أو مفاتيح أو اتصالات قواعد بيانات أو بيانات اتصال أو صور لمستخدمين حقيقيين.** أسماء متغيرات البيئة أدناه بلا قيم. لا يحتاج استخدام الملف إلى نسخ أسرار أو إظهارها في المحادثة.

## 1. ملخص المشروع وحالته

**Debit & Credit by Money Coder** منصة عربية/إنجليزية لتعلم المحاسبة بالممارسة والمحاكاة، وتحويل نتائج العمل التدريبي المقبول إلى أدلة مهارات وملف مهني وسيرة ذاتية.

الفكرة الأساسية: يتعامل المتعلم مع مستندات وحالات وقرارات وقيود وأستاذ وموازين عمل، ثم يرى أثر ما أنجزه في تقدمه وبروفايله وسيرته. الهدف ليس حفظ إجابات أو جمع نقاط فقط.

المشروع ليس ERP لإدارة أموال شركات حقيقية، ولا جهة اعتماد أو إصدار شهادات CPA/CMA، ولا منصة توظيف مكتملة تضمن وظيفة. المحاكاة لا تُعرض كخبرة عمل حقيقية، واكتمال البيانات لا يعني التأهيل المهني.

## 4. رحلات المستخدمين

### الطالب أو الخريج الجديد

```text
الرئيسية → إنشاء حساب → تسجيل دخول منفصل
→ إعداد البيانات الشخصية والتعليم للـCV لأول مرة
→ الرئيسية الموجهة / كمّل رحلتي
→ مكتب تدريب الأساس: 11 مهمة
→ أول وردية: تحقيق + قيود + يومية + مراجعة الأستاذ
→ مراجعة المهارات والأعمال
→ English CV يتحدث من البيانات والنتائج
→ استكمال الحالات والمسار المهني
```

- الحساب العائد ذو بيانات صحيحة لا يملأ النموذج مرة أخرى.
- التقدم المحفوظ يحدد الخطوة التالية، لا صورة أو نسبة ثابتة.
- تعذر تحميل البيانات يعرض حالة خطأ وإعادة محاولة، لا استبدال النتائج بصفر أو هوية افتراضية.
- اللغات تتبدل داخل الوجهة نفسها في المسارات المدعومة، دون إعادة المستخدم لبداية كل مرحلة.
- الأنشطة الإضافية تظل متاحة للاستكشاف، ولا تكون كلها دعوات متنافسة للبدء.
- المهارات والـCV نتيجة للممارسة؛ فتح الصفحة وحده لا يمنح إنجازًا.

### المحاسب العامل

يستخدم الملف المهني نفسه، مع خبراته الحقيقية وهدفه ومساره الملائم. لا تصبح كل شخصية طالبًا مبتدئًا، ولا يكتسب مسمى وظيفيًا حقيقيًا باختيار Senior أو Finance Manager داخل اللعبة.

### الزائر

يمكنه التعلم والممارسة ضمن المجالات المحلية المتاحة. تقدمه في المتصفح ليس حسابًا سحابيًا أو بيانات موثقة تلقائيًا. نقل التقدم للحساب له تدفق استيراد صريح وحدود تحقق.

### مسؤول الشركة

ينشئ مساحة شركة محدودة الصلاحية، ثم يبحث في المستخدمين الذين وافقوا على اكتشاف الشركات. اختيار المرشح يفتح بياناته المسموح بها، لا ملفه الخاص الكامل.

## 5. الدخول والتسجيل والمسارات

صفحات حقيقية في App Router:

```text
app/[locale]/login/page.tsx
app/[locale]/signup/page.tsx
app/[locale]/auth/continue/page.tsx
app/api/auth/[...all]/route.ts
```

الروابط النهائية: `/ar/login`، `/ar/signup`، `/en/login`، `/en/signup`.

- `autoSignIn: false`: إنشاء الحساب يسلّم إلى Login، وليس جلسة وهمية.
- الدخول يمر بوجهة داخلية آمنة، وإعداد البيانات الأولي عند الحاجة، ثم الرئيسية أو الوجهة المحفوظة.
- `next` يخضع للتحقق من مسار داخلي؛ لا يُقبل تحويل خارجي عشوائي.
- قيمة اللغة الحقيقية `ar` أو `en`؛ `[locale]` اسم مجلد، وليس نصًا يوضع في URL.
- الطلبات إلى `/api/auth/*` تذهب مباشرة إلى Better Auth دون بادئة لغة.
- لا إعادة كتابة إلى `/ar/api/auth/*` أو `/en/api/auth/*`، ولا تغيير مسارات `/_next` والأصول العامة والفهرسة لمعالجة Auth.
- كلمة المرور الحالية: من 12 إلى 128 حرفًا وفق إعداد التطبيق.
- الجلسة HttpOnly وSameSite، وSecure في HTTPS. لا حفظ لكلمة مرور أو session token في localStorage.
- الربط الاجتماعي التلقائي للحسابات معطل في الإعداد الحالي.

### Google والبريد

Callback المعد للمزود:

`https://debit-credit-nine.vercel.app/api/auth/callback/google`

ليس رابط بدء دخول يُرسل إليه المستخدم يدويًا. تفعيله يحتاج بيانات Google OAuth الصحيحة وإعداد العنوان لدى المزود واختبار الرحلة كاملة. وجود handler أو نجاح GET لا يثبت نجاح Google Login.

البريد المرسل يحتاج مزودًا وإعدادًا صحيحًا. التحقق والاستعادة لا يُعلنان كخدمة تعمل إذا لم تُضبط بيانات الإرسال. إعداد البريد وGoogle مستقلان عن تسجيل الدخول بالبريد وكلمة المرور، و`requireEmailVerification` حاليًا `false`.

## 6. بيانات الحساب والمصدر الموحد

البيانات الأساسية: الاسم، البريد من الجلسة، الهاتف، الدولة والمدينة، المؤسسة والمؤهل والتخصص وسنة التخرج، المستوى والخبرات الحقيقية واللغات والروابط المهنية حسب النموذج.

- البيانات الجديدة المخصصة للسيرة تُدخل بالإنجليزية؛ لا تخمين لترجمة اسم أو مؤهل.
- السجلات العربية القديمة تُقرأ دون حذفها؛ قد يحتاج صاحبها استكمال صيغة إنجليزية للتصدير.
- لا طلب لرقم قومي أو عنوان شارع أو تاريخ ميلاد لإكمال التدفق الحالي.
- الصورة اختيارية، وليست شرطًا لبدء التدريب.

إصلاح المصدر الموحد الأخير يستخدم `AccountMemberProfile` و`GET /api/v1/me/cv` لقراءة الإسقاط الحالي للمالك. الاسم والمكان والروابط والملخص لا تؤخذ من نسخة ضيف فارغة لتستبدل البيانات السحابية.

طلبات قديمة تُهمل عند تغير الحساب. حالات الخطأ واضحة، وتحديث الحفظ أو تركيز الصفحة يجدد العرض. لا ينشئ فتح البروفايل حسابًا أو سجلًا مهنيًا ثانيًا.

## 9. ورقة العمل داخل المكتب

يوجد Workbook داخل كمبيوتر المكتب، بخلايا وصفوف وأعمدة وشريط صيغة وتحديد خلية ومجاميع وفارق متجدد. لم يعد التدريب مجرد حقلي نص في صفحة خارج اللعبة.

- `C10`: صيغة جمع المدين مثل `=SUM(C2:C9)`.
- `C11`: فرق الإجماليات مثل `=C10-D10`، وفق قواعد التمرين.
- الأرصدة الأصلية والإجماليات المُعدة للرقابة لا يستطيع المستخدم تغييرها بحرية لإخفاء الخطأ.
- المحلل محدود بالصيغ المطلوبة؛ لا `eval` أو JavaScript أو اتصال خارجي داخل صيغة.
- الصيغ الخاطئة تعرض ناتجًا أو خطأ حقيقيًا، وليس نجاحًا افتراضيًا.
- المسودة غير المرسلة تبقى عند الرجوع للمكتب.
- التصدير CSV متوافق مع الجداول، وليس ملف Excel `.xlsx` كاملًا.

التمرين يثبت ممارسة ضيقة في الصيغ والمجاميع، ولا يثبت إتقان Excel أو Pivot Tables أو Power Query أو Microsoft Office.

## 16. البروفايل والكورسات والشهادات

التبويبات الحالية: Overview، Skills، Practical Work، Courses، Certificates، Career Journey. إعدادات الصورة والتواصل والمشاركة والظهور للشركات متصلة بالملف، لا صفحات هوية متنافسة بلا تسليم واضح.

### نظرة عامة

- نبذة ومعلومات أساسية وروابط مهنية في العمود الأيسر.
- أعداد حقيقية للمهارات والكورسات المكتملة والشهادات والأعمال، وشريط اكتمال البيانات.
- هدف مهني وخطوات تالية من التقدم والمتطلبات.
- ست مهارات في ملخص مضغوط، وأعمال مثبتة وشهادات موجودة فعلًا.
- الألوان الكحلي والأزرق والتركواز والأخضر والبرتقالي والوردي مستمدة من التصميم المعتمد.
- التنسيق ثابت ترتيبًا في العربي والإنجليزي، مع نصوص مترجمة وخط عربي مقروء وموبايل ووضع داكن.

### الكورسات

إضافة وتعديل وحذف كورس خاص بالحساب: اسم، جهة، تاريخ، حالة وملاحظات، مع أسماء إنجليزية اختيارية للمخرجات. الحالات: not-started / in-progress / completed. التغييرات تظهر في المصدر الحالي للـCV، لا تحتاج توليدًا يدويًا لإضافتها إلى البيانات.

### الشهادات

إضافة عنوان وجهة وتاريخ ومعرّف اعتماد اختياري وصورة؛ قراءة ومعاينة وحذف خاصة بالمالك. الصورة تحفظ نسب المستند وتُعاد معالجتها لإزالة metadata. حذف الشهادة يزيل سجلها وصورتها ومن ثم ذكرها الحالي في CV.

الكورسات والشهادات **self-reported**. لا تولد Skill Evidence أو Verified تلقائيًا. حد سجلات المحفظة مضبوط بالكود، والحد الحالي للقوائم 20؛ الصورة المشفرة لها حد منفصل 900,000 حرف، وليس تصريحًا لرفع ملفات غير محدودة.

## 17. الصور والأعمال والبطاقات وQR

### الصورة الشخصية

- JPEG / PNG / WebP، واختيار ملف حتى 5MB، مع حد إرسال مشفر منفصل.
- قياس الصورة المعالجة: 512×512، قص مركزي وإعادة ترميز وإزالة بيانات وصفية.
- دعم الشفافية عند رفع صورة تحتوي alpha؛ حفظ الصورة القديمة بخلفيتها لا يزيلها CSS تلقائيًا.
- ملكية مرتبطة بالحساب؛ لا صورة افتراضية لشخص حقيقي تُنسخ لباقي المستخدمين.
- لا صورة في ATS CV أو لوحة منافسة، ولا ظهور للشركات دون موافقة الصورة.

المعالجة الآلية لخلفية جميع صور المستخدمين ليست خدمة مكتملة. أصول cutout خاصة محلية أو معاينة QA لا تثبت تعديل صورة مالك الإنتاج.

### أفضل ثلاثة أعمال

حتى ثلاثة أعمال مثبتة من نتائج `student-unit1` المقبولة بالخادم: اليومية، أستاذ النقدية، ميزان المراجعة، وورقة العمل حسب استيفاء المهام. المعاينة تعرض العمل الفعلي والبيانات المقبولة، مع وسم Training Simulation، وليس ادعاء مشروع شركة أو خبرة عمل.

### الروابط المهنية وحالة التوفر

LinkedIn، GitHub، Facebook، Instagram، Website وفق روابط آمنة وعقود التحقق. لا يظهر رابط فارغ أو مخترع. canonical LinkedIn/Website يستخدمان عند غياب رابط مشاركة محفوظ صالح في العرض الخاص.

حالة متاح لتدريب / عمل / غير باحث يحددها الشخص، مع الدور المستهدف. الحالة ليست تصديقًا من المنصة على أهليته.

### ملخص «أنا أقدر أعمل إيه؟» وبطاقات المشاركة

الملخص يبنى من العمل المقبول بدل عبارات عامة. بطاقات الإنجاز الإنجليزية PNG مرتبطة بالمهارة والمهمة، وموسومة كمحاكاة؛ التصدير الحالي لبطاقة الإنجاز 1200×900.

الكارت المهني يجمع الهوية والصورة الاختيارية والروابط وQR، ويصدر PNG بقياس 1600×1100. خيار الصورة في الكارت لا يضيفها إلى CV أو الصفحة العامة تلقائيًا.

### الرابط العام

`/ar/portfolio/<token>` أو `/en/portfolio/<token>`، برمز مشاركة معتم وغير كاشف لمعرف المستخدم. المالك يفعله صراحة ويختار الحقول والأعمال، ويمكنه إلغاءه. QR يتولد محليًا من الرابط الحقيقي، ولا يُرسم QR مزيف عند إغلاق المشاركة.

الرابط العام يختلف عن اكتشاف الشركات. نسخه المحفوظة عند الآخرين بعد المشاركة لا يمكن استرجاعها بمجرد إلغاء الوصول اللاحق.

## 18. السيرة الإنجليزية المختصرة

تقرأ السيرة البيانات المهنية الحالية والكورسات والشهادات النصية والأدلة، بغض النظر عن لغة الواجهة. المهام المقبولة تجدد لقطة السيرة الخاصة دون تدخل يدوي من الطالب.

مواصفات المنتج:

- الإنجليزية وLTR، نص قابل للتحديد والنسخ، عمود واحد.
- عناوين معيارية مثل Professional Summary وEducation وSkills وAccounting Simulation Experience.
- الخبرة الحقيقية المدخلة منفصلة عن خبرة المحاكاة.
- لا صورة أو QR أو XP أو Coins أو لغة ادعاء اعتماد وهمي.
- صياغة مركزة تجمع النتائج المحاسبية بدل نقل كل خطوة وتاسك حرفيًا.
- كلمات دالة مدعومة بالعمل: Journal Entries، Trial Balance، Source Documents وغيرها حسب الأدلة والدور.
- الحد المطلوب في هذا المنتج **صفحتان A4**، مع قياس للطباعة واختبارات ضغط، لا تصغير خط غير مقروء لإخفاء الحشو.
- السجلات الزائدة تُنتقى للمستند مع توضيح الاستبعاد؛ لا تُحذف من البروفايل.
- السجل غير الإنجليزي يحتاج إدخال صيغة مناسبة؛ لا ترجمة آلية تخمينية للخبرة أو اسم الجهة.

الصيغ الحالية تشمل نصًا وطباعة إلى PDF من المتصفح، وتاريخ نسخ محلي ضمن التنفيذ. وجود نموذج `CvVersionCloud` لا يعني تاريخ سحابي شامل لكل نسخة لكل محرر.

تقييم ATS هو فحص تنسيق واتساق وحدود محتوى، وليس ضمان قبول لدى كل ATS أو نسبة قبول توظيف. حد الصفحتين سياسة المنتج هنا، وليس ادعاء قاعدة عالمية ملزمة لكل سيرة.

## 19. أصحاب العمل والبحث

النسخة الحالية ليست قائمة أسماء Demo في بحث الإنتاج. توجد مساحة شركة حقيقية محدودة، وصلاحية خادمية تسمح بالبحث في مرشحين وافقوا على الظهور.

الخصائص الحالية:

1. بحث بالاسم والمهارة والدور والمكان والتعليم والمستوى والتوفر، وفق البيانات التي وافق المستخدم على مشاركتها.
2. نتائج بعدد حقيقي وصفحات؛ 20 نتيجة للصفحة وفق الحد الحالي.
3. صورة المرشح فقط إذا سمح بإظهارها؛ لا خلط صور حسابات أو هوية cache قديمة.
4. قائمة مختصرة خاصة بمسؤول الشركة، مع إضافة وإزالة ومنع التكرار.
5. معاينة: Profile، Skills، Projects، Certificates، CV.
6. خمس مجموعات في نظرة المعاينة: نبذة، معلومات، مهارات، عمل مميز، شهادات نصية.
7. أزرار عرض الكل وعرض العمل تفتح تبويبات فعلية، وقائمة الثلاث نقاط تتضمن إجراء إغلاق حقيقيًا.
8. طلب تواصل داخلي لصندوق المرشح الخاص، دون كشف هاتفه أو بريده.
9. نسخة CV للشركة فقط عند موافقة CV، وبحقولها الآمنة دون جهة اتصال خاصة.

شارات المهارات تعرض عددًا أو تقاطع متطلبات فعليًا، لا أرقام Match% المرجعية. لا 124 مرشحًا أو أسماء أو صور مرجعية تُزرع في الإنتاج لملء التصميم. حسابات QA المنشأة محليًا لا تدخل قاعدة المستخدمين الحقيقية.

المساحة الحالية self-reported وبمسؤول محدود، لا تحقق رسمي للشركة أو فرق ودعوات أو نظام وظائف وطلبات وتعيين مكتمل. Jobs وAnalytics لا تُعرض كخدمات جاهزة.

حدود التنفيذ القائمة: القائمة المختصرة حتى 100، وصندوق الطلبات يعرض أحدث 20، وطلب داخلي أحدث لكل شركة ضمن العقد الحالي. البحث مبني على إسقاط JSON في PostgreSQL ويحتاج تصميمًا مفهرسًا أكثر تخصصًا عند توسع البيانات.

## 20. الخصوصية وصلاحيات العرض

| السياق         | من يصل؟          | التحكم                            |

- تفعيل اكتشاف الشركات لا يفعّل الرابط العام، والعكس صحيح.

## 21. المنافسة والإدارة

توجد ممارسة ومنافسة محلية منفصلة عن منافسة Backend. بيانات قابلة للتعديل محليًا لا تُعامل كترتيب خادمي رسمي أو دليل توظيف.

المنافسة الخادمية تتضمن مطابقة حسب الدوري والتحدي ونسخة التقييم، منع اللعب ضد النفس، قيود تفرد ومعاملات، درجة وفائز محسوبين بالخادم، إخفاء النتائج وفق شروط المباراة، ولوحة نتائج. تكرار المحاولة لا ينشئ نتيجة رسمية جديدة بلا حدود.

التحديث الحالي يعتمد Polling؛ لا يُوصف كخدمة حضور WebSocket كاملة. نتائج اللعب لا تصبح شهادة محاسبة أو Work Experience.

الإدارة محمية بصلاحية ADMIN في الخادم، وتعرض إحصاءات وبحث المستخدمين والنشاط والمنافسة. USER لا يكتسب ADMIN بكتابة role في نموذج شركة. سياسة منح الإدارة تعتمد إعداد الخادم وشروطه؛ سحب صلاحيات قائمة يحتاج سياسة صريحة، لا افتراض أن حذف بريد من قائمة يكفي دائمًا.

## 28. GitHub وVercel وRender

خط النشر المستخدم:

```text
فرع codex محدود → اختبارات وبناء ومراجعة صور
→ commit صريح بلا أسرار أو artifacts
→ push وPull Request
→ Vercel Preview READY وفحوص ناجحة
→ merge إلى main
→ Production READY بنفس SHA الدمج
→ التأكد من alias وفحص قراءة فقط
```

push أو Preview لا يكفيان لقول «اتنشر على رابط الإنتاج». يجب مطابقة SHA والرابط الثابت، لا تسليم localhost أو نشر نسخة مصدر مختلفة عن المختبرة.

Vercel هو النشر الحي المؤكد. Render بديل كان مُجهزًا بملف `render.yaml` وخدمة web وخط بناء وصحة، لكن إنشاء الخدمة واجه HTTP 402 واشتراط وسيلة دفع في المراجعة السابقة. لا يوجد نشر Render حي مؤكد في هذا الملف، ولا تفعيل مدفوعات أو نقل أسرار إليه.

`vercel.json` يمنع نشر بعض فروع الاختبار والبديل المخصصة. قواعد الاختبار وأصولها لا تنتقل إلى production بمجرد استخدام npm أو Git.

يُحدّث هذا المرجع مع كل تسليم رئيسي، ولا يُعد وجود نص هنا وحده دليل نشر. تقرير التسليم النهائي يجب أن يذكر PR وSHA وحالة Vercel والـalias التي تم التحقق منها بالفعل.

## 30. الناقص والأولويات

### أولوية تشغيل وأمان

1. إعداد Google OAuth إذا كان مطلوبًا واختباره كاملًا بإذن صاحب الحساب.
2. إعداد إرسال البريد والتحقق والاستعادة واختبار تسليم حقيقي؛ تحديد سياسة التحقق قبل فرضها.
3. توثيق ومراجعة النسخ الاحتياطية والاستعادة والمراقبة والتنبيهات وسحب صلاحيات الإدارة.
4. مراجعة إدارة عمر البيانات والحذف الكامل وحقوق المستخدم وإجراءات الحوادث؛ لا الاكتفاء بإخفاء واجهة.
5. مراقبة حدود تخزين الصور والشهادات والإسقاطات، واختبار تحميل وأداء يناسب عدد المستخدمين الحقيقي.

### أولوية منهج الطالب

1. حالات مستقلة متعددة للمستندات والموردين والعملاء والتحصيل بدل إعادة الحالة الموجهة نفسها.
2. أوراق تسوية بنكية وموردين وعملاء جديدة مع أخطاء وتوقيتات ومستندات متنوعة.
3. الأصول والسجل والإهلاك والمخزون والعد والفروق والتكلفة حسب محتوى مُراجع.
4. الاستحقاقات والمقدمات والقطع والتسويات، ثم إقفال وقوائم مرتبطة ببيانات الحالات.
5. تدريب جداول أوسع: تنظيف واستيراد وبحث وربط وفرز وتصفيات وPivot وتقارير، بمخرجات يمكن التحقق منها.
6. تقييم مستقل ذو rubrics ومصادر ونسخ وسياق مناسب قبل Verified أو شهادة اجتياز ذات ادعاء مهني.
7. مراجعة متخصص للمحاسبة والمعايير والضرائب، مع مصادر وإصدار ونطاق قضائي عند اللزوم.
8. تحسين تغطية الإنجليزية دون تخمين بيانات المستخدم أو المصطلحات غير المعتمدة.

### أولوية المنتج والبيانات

1. توسيع رحلة الطالب للوحدات التالية وتسليمها ببيانات ونتائج فعلية.
2. توسيع domains السحابية بعقود واضحة؛ لا الادعاء بأن كل نظام محلي تمت مزامنته.
3. تطوير نموذج بحث مفهرس ومقاييس أداء عند التوسع بدل الاعتماد طويلًا على JSON projection وحده.
4. إذا طُلب: وظائف وتقديم ومراحل طلبات وتحقق شركات ودعوات وفرق؛ هذه توسعة منتج لا إعداد شكلي.
5. سياسة صريحة لمشاركة جهة اتصال أو صور أو مؤهلات إضافية؛ لا توسيع كشفها تلقائيًا لإكمال المرجع.
6. إزالة خلفية صور المستخدمين إن قُررت كميزة، مع معالجة خاصة بالحساب وتكلفة وخصوصية معلومتين؛ الدعم الحالي للشفافية ليس تنفيذها.
7. اختيار بديل استضافة مجاني إن توافر للحساب فعلًا؛ ملف YAML وحده لا يتجاوز اشتراط الدفع.

هذه قائمة استكمال هندسية وتعليمية، لا ادعاء فشل الموجود أو تفويض بتنفيذ جميع البنود أو شراء خدمات.
