آخر مراجعة: 10 أكتوبر 2026.

هذا الملف يجمع تاريخ المشروع، بنيته، المنتج الموجود فعلًا، رحلة الطالب، المحتوى المحاسبي، الدخول والبيانات، الـCV والصور، الاختبارات، النشر، وحدود التنفيذ وما يحتاج استكمالًا. المرجع هو الكود الحالي وسجل Git والتقارير الموجودة بالمستودع، وليس افتراض أن كل فكرة أو صورة مرجعية أصبحت ميزة مكتملة.

لا يحتوي الملف على كلمات مرور، مفاتيح API، رابط اتصال قاعدة بيانات، بيانات طالب حقيقي، أو إعدادات حسابات خاصة. الروابط العامة وأسماء متغيرات البيئة ليست أسرارًا.

## 1. تعريف المشروع وحالته

**Debit & Credit by Money Coder** منصة عربية/إنجليزية لتعلم المحاسبة بالممارسة والمحاكاة والألعاب، والانتقال من المعرفة الأساسية إلى عمل محاسبي موثق بأدلة تدريبية، ثم عرضه في ملف مهني وسيرة ذاتية.

المشروع ليس ERP إنتاجيًا لإدارة أموال شركة حقيقية، ولا جهة اعتماد مهني، ولا موقع توظيف مكتملًا يضمن وظيفة. المحاكاة ليست خبرة توظيف فعلية. درجات الجاهزية داخل المنتج ليست قرارًا من صاحب عمل أو شهادة رسمية.

| البند | الحالة |
| --- | --- |
| المستودع | [AhmedMohamed500/Debit-Credit](https://github.com/AhmedMohamed500/Debit-Credit) |
| الإنتاج الأساسي | [الموقع العربي](https://debit-credit-nine.vercel.app/ar) / [الموقع الإنجليزي](https://debit-credit-nine.vercel.app/en) |
| فرع الإنتاج | `main`، مع فروع عمل `codex/…` وطلبات دمج |

| Google | غير متاح للمستخدم ما لم تُضبط بيانات المزود؛ فحص callback ليس إثبات دخول ناجح |
| Render | إعداد بديل محفوظ، وليس استضافة منشورة؛ إنشاء الخدمة توقف بسبب اشتراط وسيلة دفع |

## 3. رحلة الطالب الحالية

المسار الأساسي:

**زيارة الموقع → إنشاء حساب → تسجيل الدخول → بيانات الطالب لأول مرة → الرئيسية «رحلتي» → تدريب الأساس → أول وردية → أدلة المهارات → English CV → استكمال المسار المهني.**

- إنشاء الحساب لا ينشئ جلسة دخول تلقائيًا؛ ينتقل المستخدم إلى صفحة Login حقيقية باللغة نفسها.
- أول دخول يتطلب بيانات الاتصال والتعليم اللازمة للـCV. البريد يأتي من الحساب ولا يستطيع النموذج تبديل مالكه.
- المستخدم العائد الذي حفظ بيانات صحيحة يتخطى الإعداد؛ لا يُطلب منه إدخال البيانات كل مرة.
- `/ar` و`/en` ومركز `/game` يعرضون للطالب نقطة البداية نفسها، مع زر رئيسي «كمّل رحلتي» يستند إلى النتائج المحفوظة.
- عند تعذر تحميل التقدم يظهر طلب إعادة المحاولة، وليس خطوة مستنتجة من صفر افتراضي.
- المهمة الحالية تعرض «أنت هنا» وأزرار العمل الفعلية، لا رابطًا يعيد فتح الصفحة نفسها.
- في نهاية الأساس يوجد تسليم لأول وردية، وفي نهاية الوردية تسليم للمهارات، ثم للـCV.
- أدوات الحسابات والأكاديمية والتسوية البنكية والخريطة والمنافسة تظل موجودة، لكنها تحت استكشاف اختياري حتى لا تبدو كلها نقطة البداية.
- لا يُحذف تقدم قديم بسبب المسار الجديد. تظل `/student` وصيغ الروابط السابقة متوافقة.
- الخريجون والمحاسبون العاملون والزوار يحتفظون بمداخلهم السابقة؛ لا يُفرض تدريب الطالب عليهم لمجرد تغيير التنقل.

المهارات والـCV **نتيجة الشغل**، وليسا كورسين جديدين. مجرد فتح صفحتهما لا يمنح اعتمادًا أو إتمامًا. يمكن مراجعتهما مبكرًا، لكن الخطوة المقترحة تظل العمل غير المكتمل.

## 4. الواجهات والألعاب

الموقع ثنائي اللغة: العربية RTL والإنجليزية LTR. توجد أنماط فاتح/داكن/حسب النظام، وواجهات كمبيوتر وموبايل، وتنقل ولوحات وDialogs بمكونات React.

أجزاء المنتج الأساسية: صفحة التسويق، مركز اللعبة، مدينة التدريب، مكتب المستندات، أول وردية، مدينة الحسابات، الأكاديمية، مهام الممارسة والتحقيق وحركة الأموال، المسار المهني، الملف وجواز المهارات والـCV، المنافسة، الحساب والإدارة.

الرسومات الخلفية للمدن والمكاتب والشخصيات **أصول بصرية**؛ البوابات والنصوص والتقدم والأزرار عناصر واجهة فعلية. الصورة المرجعية التي يقدمها المستخدم ليست دليلًا على اكتمال وظيفة، ولا تحتوي تعليماتها المصورة على تفويض تشغيلي مستقل.

الافتتاح السينمائي الحالي له واجهة بدء وانتقال وشاشة إرشاد. وجود Poster أو عبارة عن فيديو مستقبلي لا يعني إنتاج أو تشغيل فيلم سينمائي كامل.

الملف الحالي في `lib/student/unit.ts`؛ المعالجة المملوكة للحساب في `lib/server/progress/student.ts`. يبدأ دون أرصدة افتتاحية معقدة، بالجنيه المصري، وبافتراضات تعليمية واضحة. لا يغطي هذا الملف ضريبة القيمة المضافة والإهلاك والإقفال الكامل، ولا يقدم إرشادات ضريبية.

المهام متتابعة، وتُرفض محاولة القفز للمستقبل. التصحيح على الخادم، والنتيجة الصحيحة تحفظ التقدم والدليل وتجدد لقطة CV؛ الإجابة الخاطئة لا تنشئ إنجازًا. إعادة الطلب لا تضيف دليلًا مكررًا، وتُرفض revisions القديمة وأنواع البيانات غير الصحيحة وحقن هوية مستخدم آخر.

تدريب الأساس وأول وردية شركتان/ملفان تدريبيان منفصلان في دفاترهما. ربط رحلة الطالب بينهما لا يعني دمج الأرصدة أو ترحيل قيود أحدهما إلى الآخر.

### ورقة العمل داخل كمبيوتر المكتب

لم يعد التمرين مجرد خانتين C10/C11 في صفحة نصية. يوجد داخل المكتب كمبيوتر يفتح Workbook بأرصدة فعلية وعناوين أعمدة وصفوف وخلايا ومحدد خلية وشريط صيغة وإجماليات وفارق متجدد.

- الخلايا C10 وC11 تستقبل الصيغ المطلوبة؛ الأرصدة الأصلية والنتائج المُعدة محمية من العبث.
- محلل محدود وآمن يدعم صيغ التمرين؛ لا يستخدم `eval` ولا يشغّل JavaScript أو شبكة أو دوال خارج النطاق.
- يظهر الخطأ أو الفارق الحقيقي؛ لا يعرض ميزانًا سليمًا افتراضيًا.
- تحفظ الصيغ غير المرسلة عند الرجوع للمكتب وفتح الكمبيوتر مرة أخرى.
- التنزيل الحالي **CSV متوافق مع Excel**، وليس ملف `.xlsx` أو تنفيذ Microsoft Excel كاملًا أو إثبات إتقان البرنامج.

فاتورة المورد تتطلب مراجعة المستندات الداعمة والمقارنات؛ لا يكفي إدخال قيد متزن. القرارات تشمل الترحيل أو الإيقاف أو طلب معلومات أو التصعيد. القرار الوقائي يحمي الدفتر، لكنه لا يصبح إنجاز ترحيل مكتملًا.

تُحفظ المحاولات والمساعدة والتحقيق والقرار. لا يصل قيد غير آمن أو غير متزن إلى اليومية المقبولة. إتمام الحالات الثلاث ينتج اليومية، لكن نهاية الوردية تتطلب مراجعة الأستاذ فعلًا. منطق المراحل الخمس في `lib/campaign/first-shift-hub.ts`.

اليومية والأستاذ وميزان المراجعة والقوائم وحركة الأموال والتحقيق موجودة كأنظمة تعلم وممارسة وفق تنفيذ كل وحدة. وجود صفحة تقرير لا يثبت أن كل دورة إقفال أو كل حساب مالي صار منتج Backend متكاملًا.

## 9. المنهج والتأهيل لسوق العمل

سلم المسؤولية المرجعي: **فهم → تسجيل → معالجة → تسوية → مراجعة → رقابة → تحليل → إدارة → قرار**.

المستويات L0 إلى L8 مستويات محاكاة من مبتدئ وطالب ومتدرب إلى محاسب ورئيس حسابات ومدير مالي؛ لا تمنح مسمى وظيفيًا حقيقيًا.

### التأسيس العام

مرحلة Bootcamp الحالية تتضمن 12 مهمة تأسيسية وبوس إنشاء Mizan Trading بسبع عمليات: الاستثمار، تحليل العملية، المستندات، المعادلة، الحسابات الأساسية، الإيراد والمصروف، المقابل، الزيادة والنقص، المدين والدائن، القيد المزدوج، اليومية، الدورة.

هذه مرحلة ممارسة موجهة؛ تمنح تقدم لعبة لا إثبات عمل مهني. في المسار الجديد لا تُعرض للطالب كبداية ثانية تنافس ملف التدريب المحاسبي؛ تظل متاحة عند الحاجة للمراجعة والتأسيس.

### الموضوعات المرجعية المهنية

المستندات، القيود، الأستاذ، الميزان، الدورة، القوائم، المشتريات، الموردون، العملاء، التحصيل، النقدية والبنك، التسوية، المخزون، الأصول، الإقفال، المراجعة والرقابة والتحليل والميزانيات والقرار.

الحالات الأساسية ومهام الطالب والتسوية لها تنفيذ قابل للاختبار. مراحل الشركات المتقدمة والإقفال وCorporate Bridge والمعايير والشهادات تحتوي مزيجًا من تنفيذ وأسس وخطط؛ **لا يصح وصفها كلها كتأهيل مكتمل**. المصدر التفصيلي يميز Implemented وFoundation وPlanned وReview required في `COMPLETE-ACCOUNTING-CAREER-CURRICULUM.md`.

الطالب يحتاج لاحقًا حالات أكثر استقلالية وبيانات أكثر تنوعًا ومراجعة متخصص للمحتوى، وتدريب جداول حقيقي أوسع، قبل الادعاء بجاهزية شاملة لسوق العمل.

## 10. المسار المهني والشخصيات

شخصيات الاستخدام تشمل طالبًا وخريجًا ومحاسبًا عاملًا. Career Entry يجمع نقطة البداية والدور المستهدف؛ التشخيص يقترح مستوى وفجوات، والخريطة تربط المهارات بالمهام والشركات.

اختيار الشخصية أو نتيجة التشخيص لا ينشئ خبرة في الـCV. الترقية تحتاج شروط المسار وأدلة العمل وتقييماته القائمة، وليس XP فقط. توجد خرائط ومهام وشركات ومستويات ومحتوى وأسئلة ملائمة للمرحلة.

في التحديث الأخير يأتي التشخيص والمسار المتقدم بعد إرشاد الطالب في الأساس والوردية والنتائج، بدل إرباكه بمداخل متزامنة. لا تُلغى شروط `gameHubNextMission` أو تقييمات الترقية الموجودة.

## 11. أدلة المهارات

الخط العام: **حدث عمل مقبول → تقييم جودة الحالة → دليل مهارة → جواز مهارات → جاهزية دور → عبارة محاكاة في CV**.

| الحالة | معناها |
| --- | --- |
| غير مقيمة | لا يوجد دليل كافٍ |
| Practiced | ممارسة مدعومة ضمن نطاق الحالة |
| Demonstrated | استيفاء شروط دليل أقوى حسب المحرك؛ ليس توثيقًا خارجيًا |
| Verified | ليس مكافأة لعب محلية؛ يتطلب تقييمًا مستقلًا مضبوطًا غير مكتمل حاليًا |

الدليل يحمل نطاق السيناريو والنسخة والمحاولات والمساعدة والتحقيق والنتيجة. تحفظ القواعد أثر الأخطاء، وتمنع تحويل الزيارة أو XP أو الفوز أو الشخصية إلى كفاءة محاسبية مزعومة.

تُزال ازدواجية الدليل، ويُحافظ على الفصل بين بيانات تدريب السيرفر وأدلة الحالات المحلية/النسخ الاحتياطية. تغير الدور المستهدف يعيد ترتيب المهارات والكلمات المناسبة، لكنه لا يخلق حقائق جديدة.

## 12. البيانات الشخصية والـCV

الإعداد المطلوب يشمل الاسم الكامل، الهاتف مع كود الدولة، الدولة والمدينة، المؤسسة التعليمية، المؤهل، التخصص وسنة التخرج. البريد مملوك للجلسة. اللغات وLinkedIn ورابط الأعمال والخبرة الحقيقية السابقة خيارات إضافية وفق النموذج.

لا يُطلب رقم قومي أو تاريخ ميلاد أو عنوان شارع، ولا تصبح الصورة شرطًا لبدء التعلم. يُدخل الطالب بياناته بالإنجليزية ليكون الـCV إنجليزيًا؛ لا تُختلق ترجمة لاسمه أو شهادته أو خبرته.

### مخرجات السيرة

- المستند إنجليزي وLTR حتى داخل الموقع العربي.
- عمود واحد وعناوين معيارية ونص قابل للتحديد والنسخ.
- إنجازات المهام ضمن **Accounting Simulation Experience**، لا Work Experience.
- الكلمات مثل Journal Entries وTrial Balance وSource Documents تأتي من أدلة موجودة، لا حشو بلا أساس.
- لا صورة أو XP أو Coins أو شهادات CPA/CMA مختلقة.
- المهام الإحدى عشرة تحدث لقطة CV الخاصة بالخادم تلقائيًا؛ لا يلزم فتح الصفحة أو الضغط على Generate لإضافة الإنجاز.
- النص/PDF عبر الطباعة وتصدير بيانات المهنة وتاريخ النسخ لهما حدود التنفيذ الحالية. تاريخ النسخ المحلي لا يُوصف كتاريخ سحابي شامل.
- فحص ATS الحالي فحص **تنسيق واتساق**، وليس نسبة قبول من جميع أنظمة التوظيف ولا ضمان وظيفة.

الخادم والواجهة يقيدان الملكية. السيرة والاتصال لا تُنشر في لوحة المنافسة. واجهات أصحاب العمل الحالية تتضمن بيانات Demo وليست قاعدة متقدمين حقيقيين موثقة.

## 13. الصورة والملفات الشخصية

رفع اختياري بصيغ JPEG/PNG/WebP، بحد ملف 5MB. تُقص الصورة مركزيًا إلى مربع **512×512**، وتُعاد معالجتها لإزالة البيانات الوصفية. تظل خاصة بالحساب ومفصولة عن نسخ التقدم العامة والمنافسة والـCV.

الصورة تظهر في مواضع بروفايل اللاعب والملف المهني المدعومة، وتُحذف من إعداداتها مع استمرار الحذف بعد إعادة التحميل. ليست ألبوم صور أو رفع ملفات عام.

مشكلة الإطار الأخير: دائرة 44×44 داخل مربع 70×70 كانت تترك مساحة ملونة. أصبحت الصورة تملأ عرض وارتفاع إطار الملف مع `object-fit: cover` وزواياه؛ على الموبايل تملأ الإطار الأصغر أيضًا.

الأسماء المتشابهة ليست صلاحيات متشابهة:

- `/profile`: ملف اللعبة وإعداداته القديمة.
- `/account`: الحساب السحابي والجلسة.
- `/student-profile`: بيانات السيرة المطلوبة.
- `/career-profile`: الملف المهني والمهارات والسيرة وإعداد الصورة/البيانات المتاحة.

التنقل الأساسي للطالب يركز على ملفه المهني بدل عرض كل هذه الوجهات كبروفايلات متنافسة؛ المسارات القديمة لم تُحذف.

## 14. التسجيل والدخول

توجد صفحات فعلية في App Router: `app/[locale]/login/page.tsx` و`app/[locale]/signup/page.tsx`.

الروابط النهائية: `/ar/login`, `/ar/signup`, `/en/login`, `/en/signup`.

Better Auth يستخدم `app/api/auth/[...all]/route.ts` للـGET/POST. نطاقه `/api/auth/*` دون لغة. callback الخاص بـGoogle هو:

`https://debit-credit-nine.vercel.app/api/auth/callback/google`

ذلك عنوان إعداد المزود، لا رابط بدء دخول يُرسل له المستخدم يدويًا. وجهة المستخدم بعد المصادقة مختلفة وآمنة وداخل الموقع؛ تمر عند الحاجة عبر `/auth/continue` للتحقق من بيانات الطالب.

لا توجد إعادة كتابة لغة على `/api/*` أو `/_next/*` أو الأصول العامة أو favicon/robots/sitemap. لا يستخدم النص `[locale]` كقيمة URL. ضبط `BETTER_AUTH_URL` يكون لأصل التطبيق، لا `/ar` أو `/api/auth`.

غياب Google لا ينبغي أن يعطل الدخول بالبريد المستقل. إرسال التحقق أو استعادة كلمة المرور يحتاج مزود بريد وإعدادًا واختبارًا؛ لا يظهر نجاح إرسال وهمي. الحد الحالي لكلمة المرور الجديدة 12 حرفًا وفق سياسة المشروع.

## 15. الأخطاء السابقة وعلاجها

| المشكلة | ما ثبت وعُمل |
| --- | --- |
| Next.js 404 للمصادقة | URL المثبت كان `/api/auth/callback/google`. الإنتاج كان على `684efc1` دون صفحات/API Auth، بينما التنفيذ لم يُنشر. عولج نشر المصدر الصحيح وأضيفت اختبارات المسارات؛ لم تكن هناك بينة على عطل DB وراء هذا 404. |
| الدخول غير متاح | إعدادات الخادم كانت غائبة في مرحلة سابقة، ثم فُعّل اتصال الإنتاج. Google والبريد المرسل مستقلان؛ لا تُعامل كل الأزرار كخدمات تعمل. |
| صور غير واضحة | تمت مراجعات وضوح وتصميم؛ بعض تغييرات التسويق تراجعت في Git. الشكل المعتمد يُراجع من الأصول الحالية، لا من كل تجربة سابقة. |
| Timeout في الوصول | `ERR_CONNECTION_TIMED_OUT` ليس 404. فحوص خارجية نجحت؛ لم يثبت أن السبب DB أو أن النشر مفقود. جُهز بديل Render دون تسريب أسرار. |
| إنشاء Render | HTTP 402 طلب وسيلة دفع؛ لم تُنشأ خدمة أو رابط نشر، ولم تُفعل مدفوعات. |
| Sign up لا يسلّم لتدفق مناسب | أصبح إنشاء الحساب ثم Login منفصلًا، ثم بيانات الطالب لأول مرة، ثم الرئيسية. |
| تدريب منفصل عن اللعبة | نُقل إلى المدينة ومكتب المستندات، مع حفظ التقدم القديم. |
| Excel في مكان غير مناسب | نُقل إلى كمبيوتر المكتب وWorkbook فعلي داخل الواجهة، دون الادعاء بأنه Excel كامل. |
| صورة صغيرة داخل الإطار | أُصلحت أبعاد المكوّن الداخلي لتملأ الإطار كله. |
| التوهان | أضيفت بداية واحدة وتسليم بين المراحل ومؤشر «أنت هنا» وخطوة تالية حقيقية. |

لا يُغيَّر نظام محاسبي أو تُمسح قاعدة البيانات لمعالجة مشكلة URL أو تصميم.

## 16. الـBackend وقاعدة البيانات

الـBackend داخل Next.js، مع PostgreSQL وPrisma وBetter Auth وخدمات سيرفر منظمة وAPI v1. التهيئة الكسولة تسمح بالبناء دون أسرار الإنتاج، مع فشل واضح وغير مزيف عند تشغيل خدمة ناقصة الإعداد.

مخطط Prisma الحالي يضم 25 نموذجًا:

`User`, `Session`, `Account`, `Verification`, `RateLimit`, `PlayerProfile`, `UserPreference`, `CloudProgress`, `ProgressSnapshot`, `LegacyImport`, `UserActivity`, `CareerGoal`, `CareerProfileCloud`, `SkillEvidenceCloud`, `CvVersionCloud`, `MissionAttempt`, `CaseAttempt`, `CaseEvent`, `AcceptedOutcome`, `CompetitionPlayer`, `CompetitionQueue`, `CompetitionMatch`, `CompetitionMatchPlayer`, `CompetitionAttempt`, `AuditLog`.

وجود نموذج لا يعني اكتمال كل APIs المرتبطة به؛ بعضه أساس توسع. الملكية بمعرف المستخدم لا بعنوان البريد. توجد مفاتيح وفهارس وقيود تفرد للمحاولات والنتائج والطوابير والأوامر ونسخها.

المهاجرات الحالية إضافية ومتسلسلة. توليد Prisma Client أثناء البناء لا يطبق مهاجرات أو seed أو reset. التحديث الحالي للرحلة والصورة لا يغير المخطط أو يطبق ترحيلًا.

واجهات المصادقة منفصلة عن `/api/v1/[...path]`. من واجهات الطالب الخاصة: `me`, `me/personal`, `me/photo`, `me/student-unit`, `me/cv`, `me/progress`. توجد خدمات Foundations والتسوية والمنافسة والإدارة والترحيل وفق العقود الحالية.

## 17. المحلي والسحابي

| المجال | حدود الحفظ |
| --- | --- |
| الزائر | تقدم محلي بالمتصفح، لا حساب سحابي تلقائي |
| الجلسة والهوية والملف الأساسي | خادم وقاعدة بيانات |
| بيانات الطالب وصورته | خاصة بمالك الحساب على الخادم |
| ملف تدريب الطالب | نتائج مصححة بالسيرفر ودليل ولقطة CV خاصة |

| اكتشاف مدينة الحسابات والممارسة القديمة | محلي ضمن نطاقها؛ لا مزامنة مفترضة لكل مفتاح |

توجد آليات Outbox مستقلة لكل حساب، ومسودات وrevisions وحالات saved/pending/unsynced/conflict. لا يُخلط «موجود محليًا» بـ«محفوظ على الخادم». الاستجابات المتأخرة لا تكتب حسابًا آخر.

استيراد تقدم الزائر صريح بخيارات دمج/الإبقاء/مراجعة، مع إصدار وجهاز وchecksum ومنع التكرار. لا تصبح أدلة Legacy أو النقاط المستوردة Verified. قاعدة الاختبار المعزولة لا تستبدل قاعدة الإنتاج.

## 18. المنافسة والإدارة

توجد منافسة محلية/شخصيات على المتصفح ومنافسة Backend محمية؛ يجب التمييز بينهما.

منافسة السيرفر تشمل انتظارًا ومطابقة متوافقة حسب الدوري والتحدي ونسخة التقييم، ومنع مباراة المستخدم مع نفسه، ومعاملات وتفرد، وحساب الدرجات والفائز بالسيرفر. توجد قيود المحاولة الرسمية، وإخفاء الإجابات/النتائج حتى شروط انتهاء المباراة، ولوحة أسبوعية. تكرار المحاولة ممارسة لا نتيجة رسمية ثانية.

التحديث الحالي يعتمد Polling، لا حضور WebSocket أو خدمة multiplayer مستقلة مكتملة. نتائج المنافسة لا تنتقل تلقائيًا إلى خبرة وظيفية في السيرة.

الإدارة محمية بالسيرفر، وتعرض إحصاءات وبحثًا وتصفيات وصفحات للمستخدمين والنشاط والمنافسة. الشخصية المهنية ليست صلاحية ADMIN؛ الترقية تتبع سياسة البريد الموثق وقائمة الإدارة. سحب صلاحية سبق منحها يحتاج سياسة مكتملة؛ إزالة البريد من القائمة وحدها ليست ضمان سحب تلقائي.

## 19. الأمان والخصوصية

- الجلسة Cookies بـHttpOnly وSameSite؛ Secure عند HTTPS؛ لا تحفظ كلمة مرور أو token جلسة في localStorage.
- Better Auth يتولى hashing وCSRF وحالة OAuth؛ الربط الاجتماعي التلقائي له حدود تمنع ربطًا غير آمن بالبريد وحده.
- APIs الخاصة تعتمد الجلسة، لا `userId` مرسلًا من المتصفح كتصريح ملكية.
- Strict schemas وحدود JSON وOrigin checks وrate limits وأخطاء معقمة وno-store.
- `X-Account-Context` يكتشف تغير حساب تبويب؛ لا يمنح صلاحية.
- الهاتف والبريد وبيانات السيرة والصورة لا تدخل لوحة المنافسة العامة.
- الصور يعاد فحصها ومعالجتها؛ metadata لا تُحفظ كدليل أو تُنشر.
- `.env.local` والاتصالات ومفاتيح المزودين والتقارير الخاصة والأصول الاختبارية ليست ملفات للنشر.
- لا اختبار كتابة بحساب طالب حقيقي، ولا reset أو seed للإنتاج، ولا نقل أسرار لـRender لمجرد تجهيز ملف استضافة.
- لا ضمان مطلق أن المنتج «آمن بالكامل»؛ الأمان يحتاج مراجعة وصيانة واستجابة حوادث مستمرة.

## 22. التشغيل والاختبارات

التشغيل المعتاد:

```sh
npm install
npm run dev
npm run check
```

التجربة عند `http://localhost:3000/ar` أو `/en`. تهيئة قواعد البيانات وAuth عملية منفصلة عن تشغيل واجهات الضيف؛ لا يوضع سر في الكود أو الشات.

`npm run check` = ESLint دون warnings + TypeScript + اختبارات + Production build. نتيجة التحديث الحالي: **583 اختبارًا في 68 ملفًا، والبناء ناجح**.

أداة الطالب `scripts/student-cv-browser-qa.mjs` نجحت في **313 فحصًا**: العربية والإنجليزية على 1440 و390 بكسل، بيانات أول دخول، الصور وملء إطارها، المهام الإحدى عشرة، ورقة العمل، CV، الخصوصية والخروج وإعادة الدخول واستعادة الخطوة التالية. في الإنجليزية على الكمبيوتر استكملت التحقيق والترحيل للحالات الثلاث ومراجعة اليومية والأستاذ ثم المهارات والـCV فعليًا.

أداة `scripts/auth-routing-browser-qa.mjs --signup-signin-home` نجحت في **229 فحصًا محليًا** لمسارات التسجيل والدخول والخروج والرئيسية. أدوات الإنتاج تُشغَّل بوضع القراءة فقط؛ نجاح المحلي لا يُسجل كاختبار دخول Google أو حساب إنتاج حقيقي.

تنتظر أدوات QA تهيئة واجهة الجلسة قبل تعبئة نموذج الطالب، واستقرار صفحة Auth قبل إرسالها؛ نموذج SSR المؤقت قد يُستبدل أثناء hydration. لا تُلغى حماية rate limits لتسريع الاختبارات.

مخرجات الصور والتقارير تحت `artifacts/` محليًا. `scripts/student-production-readonly-qa.mjs` و`--production` لأداة Auth يتحققان من الصفحات وحماية APIs دون إنشاء حسابات وهمية على الإنتاج.

## 23. GitHub وVercel وRender

الاستضافة الأساسية Vercel، عبر ربط المستودع. التسلسل السليم: فرع محدود → commit نظيف → push → Pull Request → Preview جاهز وفحوص ناجحة → merge إلى main → مطابقة SHA لنشر Production → فحص قراءة فقط.

آخر قاعدة منشورة قبل التحديث الحالي هي دمج PR #12 عند `d3ac6af63da27e00b524ee8d22a4bfd792aa40db`. هذا مرجع تاريخي للنسخة التي بدأ منها ربط الرحلة؛ لا يُقصد به تثبيت main عنده بعد أي نشر جديد.

أسماء المتغيرات ذات الصلة، دون قيم: `DATABASE_URL`, `DATABASE_DRIVER`, `DIRECT_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `RESEND_API_KEY`, `EMAIL_FROM`, `ADMIN_EMAILS`. يحدد الكود ما هو مطلوب أو اختياري؛ لا تُنسخ كل إعدادات المحلي إلى الإنتاج عشوائيًا.

Render بديل **مُجهز وغير منشور**. لا رابط Render صالح للتسليم، ولا خدمة تم إنشاؤها، ولا دفع مفعّل. تعارض الوصول الشبكي يُشخَّص بصورة مستقلة عن كود المسارات وقاعدة البيانات، مع الحفاظ على إنتاج Vercel.

## 24. ما تم في التحديث الأخير

1. جعل صورة الملف المهني تملأ إطارها على الكمبيوتر والموبايل.
2. إضافة منطق موحد للخطوة التالية قائم على بيانات الحساب و11 نتيجة أساس والمراحل الخمس الفعلية لأول وردية.
3. تحويل الرئيسية ومركز اللعب للطالب إلى «رحلتي» بدل عدة بدايات متنافسة.
4. إضافة ترتيب واضح ومكان حالي وتسليم بين التدريب والوردية والمهارات والسيرة.
5. تقليل التنقل الأساسي للطالب مع إبقاء الأنشطة الأخرى اختيارية والمسارات القديمة محفوظة.
6. إخفاء رابط البداية القديمة المتكرر في سياق الرحلة الموجهة، دون حذفه من واجهات الضيف والأنماط الأخرى.
7. إبقاء صفحة الملف الحالية عند تبديل اللغة، بدل الرجوع دائمًا لمقدمة الملف.
8. إصلاح تعارض خلفية العالم القديم مع نص الرئيسية، وفحص صور الموبايل والكمبيوتر.
9. اختبارات حسابات منفصلة وتحديث بعد المهمة وحالات الخطأ والتحميل وعدم اصطناع إتمام.
10. توثيق تفصيلي لهذا التغيير في `CONNECTED-STUDENT-JOURNEY-AR.md`، وتجميع المشروع في هذا الملف.

ملفات المحور: `lib/student/journey.ts`, `components/student/student-journey.tsx`, `app/student-journey.css`, `app/profile-photo.css`، وربطها بـStudentWorld وGameHub وPlatformNav وStudentUnit وFirstShift وCareerProfile. لم تتغير قواعد القيد أو المخطط أو بيانات الإنتاج.

## 25. ما يحتاج استكمالًا

### أولوية التشغيل

- إعداد Google OAuth وإثبات دخول كامل بحساب مالك مخول، إذا أُريد تفعيله.
- إعداد البريد المرسل والتحقق واستعادة كلمة المرور واختبار التسليم الحقيقي؛ لا الاكتفاء بوجود زر.
- اختبار دخول إنتاج فعلي بإذن المالك، دون إنشاء بيانات تجريبية في قاعدة الطلاب تلقائيًا.
- توثيق إجراءات النسخ الاحتياطي والاستعادة والمراقبة وسحب أدوار الإدارة بما يناسب بيئة الإنتاج.

### أولوية المنهج

- حالات مستقلة إضافية للموردين والعملاء والبنك والمخزون، لا تكرار الحالة الموجهة نفسها.
- Excel/جداول أوسع: تنظيف واستيراد بيانات، بحث وربط، فرز وتصفيات، Pivot وتقارير؛ التمرين الحالي لا يثبت هذه المهارات.
- تسويات وإقفال وإهلاك ومخصصات وضوابط ومراجعة وقوائم مترابطة بعمق أكبر وفق خطة المنهج.
- مراجعة محاسبية متخصصة لكل موضوع متقدم، وبالأخص المعايير والضرائب والمناطق القضائية؛ لا تقديم «امتثال» بلا مراجعة.
- تقييم مستقل مضبوط ومعايير نجاح واضحة قبل إنشاء Verified أو شهادة اجتياز مهنية.
- ترجمة إنجليزية معتمدة للتفاصيل التي ما زالت بمصدر عربي.

### أولوية المنتج والبيانات

- توسيع domains السحابية صراحة، لا الادعاء أن كل نظام محلي أصبح سحابيًا.
- توسيع رحلة الطالب إلى الوحدات التالية مع تسليم واضح وبيانات حقيقية، دون اختراع صفحات أو إتمام لم يُنجز.
- تحسين تجربة أصحاب العمل والتوظيف الحقيقي إن تقرر بناؤها؛ الـDemo الحالي لا يستقبل متقدمين حقيقيين تلقائيًا.
- استضافة بديلة دون مدفوعات فقط إذا كانت متاحة فعلًا للحساب؛ إعداد YAML لا يحل شرط وسيلة الدفع.

## 26. قواعد استكمال المشروع وتسليمه

1. اقرأ هذا الملف و`STATUS.md` وملفات المجال قبل تعديل نظام موجود.
2. افحص `git status`، واحفظ تغييرات المستخدم والملفات غير المرتبطة بعملك.
3. لا تحذف Better Auth أو أعمال الـBackend لعلاج 404، ولا تنشئ `/ar/api/auth`.
4. لا reset لقاعدة الإنتاج، ولا migrate/seed من build، ولا استبدالها بقاعدة اختبار.
5. لا تغيّر حسابات الدليل أو القواعد المحاسبية دون طلب ومراجعة واختبارات.
6. لا تمنح Verified أو خبرة توظيف من XP أو قراءة أو persona أو بيانات قابلة للتعديل محليًا.
7. لا ترسل الأسرار أو بيانات الطلبة في الشات والتقارير والمستودع والصور العامة.
8. اختبر العربية والإنجليزية والموبايل والكمبيوتر، ونهاية كل مرحلة وبداية التالية، وحفظ المسودات وإعادة الدخول.
9. انشر المصدر الذي اختُبر، وطابق SHA وحالة Production. لا تقل «اتنشر» اعتمادًا على push أو Preview فقط.
10. إذا غُيّر الاسم مستقبلًا، فاسم قاعدة الخدمة الإداري لا يفرض اسم المنتج. يلزم جرد العلامة والأصول والmetadata والنطاقات وإعدادات OAuth والبريد، مع الحفاظ على معرفات البيانات ومفاتيح الحفظ أو ترحيلها صراحة. لا تغيّرها باعتبارها نصوصًا شكلية فقط.
